# AGENTS.md

This file is for agents / developers joining this repository later, and records CafebeeAI's **project consensus, key rules, and hard-won gotchas**. Read it fully before rewriting any implementation; append new library constraints or gotchas as you run into them.

## Project Consensus

- **CafebeeAI**: an LLM chat app whose workspace is a directory (Project). iOS/Android (bare RN CLI 0.85.3 / React 19 / TypeScript 5.8). This repo currently ships only the Android native project (no ios directory), but the code stays portable to both platforms (react-native-paper / navigation / blob-util / documents-picker / share all support both).
- **UI library**: react-native-paper (MD3, warm-white newsprint / light / dark / follow system, **newsprint by default**); navigation: @react-navigation/native-stack + drawer; state: valtio.
- **LLM**: hand-written OpenAI Compatible client (`src/llm/openai-client.ts`: XHR streaming + self-implemented SSE parsing + incremental tool_calls aggregation; `chat.ts` implements the multi-step agent loop itself). OpenAI Compatible only.
- **Long chat list**: `@shopify/flash-list` v2 (inverted mode).
- **Zero automated testing** (no unit tests / no E2E); acceptance is manual.
- Language: all copy centralized in en-US (no i18n framework); Android identity (versionName, versionCode, applicationId) is **dotenv-only** (rule 32); `package.json` `version` is metadata kept manually in sync.

## Data Layout (private sandbox, invisible to users)

```
iOS: <Library>/Application Support/cafebeeai/     Android: <filesDir>/cafebeeai/
├── providers.json            # global provider registry (no secrets)
├── system-prompts.json       # global System Prompt registry (no secrets) - see Key Rule 35
├── skills.json               # global Skills registry (no secrets) - see Key Rule 36
├── (secrets)                 # API keys + custom Header values now live in EncryptedStorage (Keychain / EncryptedSharedPreferences), NOT in a file - see Key Rule 29
├── project-meta/             # app-owned per-project state (moved out of the Project dir, 2026-11-18; breaking change, no migration)
│   └── <uuid-nodashes-lowercase>/
│       ├── config.yaml            # kind: v1/config
│       ├── chats/<uuid>.json      # one file per conversation (conversation+messages), atomic writes
│       └── ui/conversation_<uuid>.json  # per-conversation UI state (draft + lastReadId), high-frequency small writes, never in exports
└── projects/
    └── <uuid-nodashes-lowercase>/     # default project = all-zero uuid (cannot be deleted/renamed, display name "Default")
        └── <user files...>                  # PURE user files (flat in the root) - no app state lives here
```

A Project directory is pure user files (tools/git/export/static-server need no metadata special-casing); deleting a project unlinks BOTH trees (`projects/<uuid>/` + `project-meta/<uuid>/`, non-atomic - the orphan sweeper reconciles). **Orphan sweeper** (`core/project-sweeper.ts`, fire-and-forget at `kApp` bootstrap, one run per 14 days keyed on `<appRoot>/project-sweeper.json`, no record = run on first startup): (1) `project-meta/<uuid>/` with no `projects/<uuid>/` -> delete the meta tree; (2) `ui/conversation_<id>.json` with no `chats/<id>.json` -> delete the ui-state file; (3) the inverse (project without meta) is legitimate and untouched (write paths `ensureDir` on demand); `exports/` keeps its own 24h TTL sweep.

Exporting a Project = a full zip (user files +, with an "Include chat history" toggle, the project-meta content under the zip's `.cafebeeai/` interchange folder - the zip format is stable across versions; `ui/` state never enters the package) -> temp directory -> system share sheet. Importing routes the zip's `.cafebeeai/` back into `project-meta/<id>/`.

## Key Rules (Non-negotiable)

1. **No imperative native RN UI**: `Alert` / `ToastAndroid` / `ActionSheetIOS` are all banned. Confirmations/dialogs use **AppDialog** (`src/ui/components/app-dialog.tsx`; subcomponents keep `AppDialog.Title/Content/Actions/ScrollArea`, Portal already built in), **failure/validation notices (validate failed, import/export/save/delete failed, invalid name, ...) use the problem-notice confirm dialog** (`showNotice(message, { title })` in `src/state/notice.ts`, rendered with a single OK button by `GlobalHosts`), success light feedback uses Paper Snackbar (`showToast`), menus use Paper Menu. **Paper `Dialog` / Paper `Modal` are banned** (they render incorrectly under the new architecture; see the gotcha entry).
2. **Pressable is only the event layer**: do not rely on Pressable's `style` (including function styles / pressed state). Styles live on an outer `View`; press feedback goes through controlled state changing the outer style. Centralized in `src/ui/components/app-pressable.tsx`.
3. **Tool scope locked to the Project directory**: `read_file` / `write_file` / `list_files` / `search_files` / `edit_file` / `download_file` (plus `show_form`); paths are normalized and then verified to be inside the project root, and the reserved `.git` segment is rejected (prevents `../` escapes and the model eating repo internals; app state lives outside the Project in `project-meta/`, so nothing else needs reserving; **all other hidden files/directories are allowed**, e.g. `.env`/`.gitignore`/`.github/` - the Project files page lists and manages them the same way, Rule 19).
4. **`write_file` / `edit_file` / `download_file` require user confirmation = inline on the tool_call card (no popup)**: a write-tool card awaiting confirmation is itself the confirmation UI - inline **[Reject]/[Approve]** buttons (fixed order: Reject left, Approve right; **Approve is always the theme-toned `primaryContainer` pill - never an error/red background, even when overwriting**; the overwrite warning surfaces only in the read-only preview; the download card inserts a **neutral-outline [Open] between Reject and Approve** - inspection-only, it first shows the "Open external URL" ConfirmDialog and then `Linking.openURL`, never approving/rejecting, the card stays Pending), tapping the card body opens a **read-only preview** Dialog (path + overwrite warning + scrolling content preview / for edit, two blocks contrasting "original" vs "replace with", each capped at 8 lines + an omitted-lines hint) - **except download_file, whose body tap is unified with every other card: it opens the full-screen ToolDetail page** (full URL/path; a pending download carries an approvalNote there = overwrite warning when the target exists + "The file is downloaded after approval.", because the fetch happens only on Approve); action buttons **appear only on the pending card of the newest record**, and a single click takes effect with no second confirmation; once resolved the card collapses back to one read-only line. There is **no** "don't ask again in this session" checkbox (sessionAllowed and the confirm-dialog host have both been removed). **Two approval layers**: app-level "Auto-approve writes" toggle (`state/settings.ts` `autoApproveWrites`, memory-only, resets to off on cold start, one-time ConfirmDialog before enabling; it governs download_file too) > per-card confirmation (default). **Approve = execute the frozen snapshot**: approval writes exactly the card's content to disk, without re-checking a file fingerprint; if the file was changed externally while confirmation was pending, the user tells the model "I've updated XX, please take another look" to drive a re-read (for download_file the frozen snapshot is **URL + target path**; the body is fetched at execution time). Reject returns `The user rejected this write request` (download card: `The user rejected this download request`); stop/preempt/delete returns `user_cancelled` (the card shows "Cancelled"; an in-flight download additionally cancels the native task via the turn's abort signal handed to `ToolExecContext.signal`). Confirmation-bridge pendings and cancellations are all scoped by `(projectId, convId)` (`cancelWriteConfirmationsFor`) so parallel sessions never hurt each other.
5. **File-type whitelist**: attachments and `read_file`/`edit_file` handle only text + common code extensions (html/css/js/ts/py/java/go/rs/c/cpp/sh/sql/xml/toml/csv/md/json/yaml, etc.). Binary files are managed only, never fed into the prompt. `read_file` **truncates above 64KB** with a notice. `download_file` may store **any** file type (CDN assets include fonts/images; the whitelist only gates what enters the prompt, not what lands in the Project). Attachments appear only in **historical messages** (the input bar no longer offers "attach a file to the message"; files are imported via the Files panel -> project files page, and the model reads them with `read_file`).
6. **No retry-on-failure button**: on failure the chat keeps a persistent error record (deletable); "Regenerate" = replace the target message and re-run the whole turn (including tool replay; write operations get confirmed again). Internal automatic retry allows at most 3 attempts (network / empty stream / decode / 5xx / 429 / **request-level timeout** only; user stops are never retried). **Timeouts only bite HTTP requests, never the flow**: network-silence detection lives down in openai-client as a request-level `idleTimeout` (default 120s, reset by any received bytes; when it fires it throws `LLMIdleTimeoutError`, classified as a retryable network error); tool execution / card confirmations / form waits have **no timeouts at any point** (waiting on a human is a legitimate state); the turn-orchestration layer runs no watchdog whatsoever. The download_file exception is still request-level, never flow-level: its own HTTP GET carries a **300s no-data stall watchdog** (re-armed by every stream progress tick, cancels the native task; the human wait before approval is unbounded) plus a 50MB streamed-size cap.
7. **Streaming semantics (multi-session parallelism WIP)**: **true parallelism across sessions/projects** (no concurrency cap); within one session only one turn at a time. Stop = interrupt and keep the already-generated part + a marker (stops only that session); network loss mid-stream = keep the partial output + a failure record; 120s of network silence fails that request (see Rule 6); switching session/project never interrupts running turns - background turns keep writing the registry and persisting periodically.
8. **Preference persistence**: changes to `prefer_provider`/`prefer_model`/`display_name` are written to `project-meta/<id>/config.yaml` with a 500ms debounce and validated with zod; **only a `kind` mismatch or structural corruption counts as an empty preference** - missing fields are tolerated via a partial parse. **`loadConfig` automatically merges debounce deltas not yet flushed (`pendingDebounce`) at read time**, otherwise switching Provider and immediately returning to the chat page (focus refreshes modelBar) would read the pre-flush stale value and the indicator would not update.
9. **Exported markdown contains only the final Q&A text** (no reasoning/tool records); filename `<conversation name>-<timestamp>.md`.
10. **Model selection (session-level sticky binding)**: priority = Conversation metadata `providerId/model` (a pick in the modelBar or before sending is written immediately and persisted; affects only the next turn, never interrupts a running turn) > project preference `prefer_provider/prefer_model` (the default for older sessions with no binding, updated in sync when a choice is made) > fetching `/v1/models` and letting the user pick > manual entry; if the bound provider has become invalid -> pop the selector before sending to rebind (never silently fall back to another provider + stale model). The selection UI is the Root Stack full-screen page `ModelPicker` (`ui/screens/chat/model-picker.screen.tsx`), **not a modal/Dialog**; callers still `await openModelPicker(...)`, and it auto `goBack()`s to the chat page after a choice. **Lists (single-provider mode and within each group of the all-providers view) are always sorted lexicographically by model name with `localeCompare`**. On the chat page, the provider/model tag bar at top (`modelBar`) has its entire row as an `AppPressable` so any part of it opens the picker (the gear / top-right cog is just the icon for the same entry point - never leave the row unresponsive); label text resolution order = session binding -> project preference (consistent with `resolveSendTarget`). The Provider form page's "Model preview" likewise renders a single-column `MarkdownBlock` table (lexicographic order), not flex-wrapped chips. **ModelPicker group headers (provider names) use bold `onSurface`, never `primary`** (list items are chips themselves, whose color comes from chip semantics). **System Prompt switching is a parallel session-level quick switcher**: the prompt-initial roundel button at the input bar's left edge (beside `+`; **not an icon font** - the bound prompt's first character/letter centered in a small circle ringed in `theme.colors.primary`, monospace 600, re-derived on every binding/registry change; `ChatInputBar` -> AppDialog `ui/screens/chat/system-prompt-picker.tsx`, row tap = apply + dismiss) persists `Conversation.systemPromptId` through `updateConversationMeta` on the same immediate-write / next-turn-only channel (absent id = the built-in Ask; a deleted prompt falls back lazily - see Rule 35).
11. **Every native `Text` must explicitly receive a theme color**: RN's default `Text` color does not follow the Paper theme (black text even in dark mode). Bubble body text always goes through `MarkdownBlock content color=...` (user = `onPrimaryContainer`, assistant = `onSurface`); Dialog body text uses Paper `Text` or an explicit `theme.colors.onSurface`.
12. **Message row layout**: **user row = [content], with no right-side avatar slot**; only user questions are drawn as a bubble (`primaryContainer`, `maxWidth: "82%"`), and there is **no three-dot icon on the right**. The user menu opens via **long-press on the bubble** (Menu anchor coordinates = the long-press point `pageX/pageY`; the Portal sits outside the mirror layer so inverted `scaleX:-1` does not affect it; `MarkdownBlock selectable={false}` inside bubbles - otherwise on Android the long press gets hijacked by text selection and no menu appears). assistant row = **article with flex:1**: replies use article typography (**no bubble background, no AI avatar**), **no right-side avatar slot**, but **keep the same row padding baseline as user bubbles** (row padding 14; never use negative margins to hug the screen edge); tool-call cards / reasoning blocks / body text / footer all align on the same side without indentation; **footer row at the bottom of the article**: gear `cog-outline` (`AppPressable` + `Icon size=14`, box height 18, **left of the text**) opens the action menu (**the entire footer row is an `AppPressable` - the gear, "Reply complete", and inline blank space all open that menu**; the body text area responds to no taps - do not wrap the whole article in a pressable again, it fights text selection/scrolling) (includes an **"Expand answer"** entry -> stored via `state/answer.ts`, then `navigation.navigate("AnswerFull")` for the full page, see Rule 26) + small text (11) "Reply complete" (shown when `state === "done"`/default, or **while waiting for human approval** - while waiting, the bubble presents as "Reply complete" with no "Generating…" badge; the pending-confirmation/pending-form card is itself the status); **the footer is not rendered while streaming over the network / executing tools**; that row is reserved for future tok/s, counters, and similar information - do not reintroduce IconButton or a separate left-column gear; **bubbles on the chat page are always `selectable={false}`** (text selection in assistant replies happens only in the AnswerFull page). AI replies pass **`compact`** to `MarkdownBlock`: codeblocks/tables and other block elements shrink to tool-card-level font size (12) / icons (12~14) / padding (6~8); markdown **supports GFM tables** (`markdown.tsx` `matchTable`/`MarkdownTableBlock`: columns split the screen width equally; after measurement, when there are long URLs/code or many rows, switch to natural width + horizontal scroll).
13. **The single source of app icons = `iconkitchen/` (export directory); app-side files are merely its install artifacts**: to change icons, first update `iconkitchen/`, then sync into `android/app/src/main/res/mipmap-*/` (`ic_launcher` / `_background` / `_foreground` / `_monochrome` x 5 densities) and `android/play_store_512.png`; `mipmap-anydpi-v26/ic_launcher.xml` keeps the adaptive (background+foreground+monochrome) references. `iconkitchen/ios` and `iconkitchen/web` are not consumed by the current (Android-only) project but are kept in sync. **In-app copy**: the About page hero renders the app's own launcher artwork as `src/ui/assets/app-icon.png` (512x512 full-bleed, sourced from the `sketch/appicon.png` master) - re-export it whenever the icon set changes; it is a deliberate exception to the bitmap ban, which still applies to **brand** icons in `src/ui` (those use the MaterialCommunityIcons font, never bitmaps).
14. **All project text is en-US - user-facing and model-facing alike (public release)**: model-facing strings include `DEFAULT_SYSTEM_PROMPT` in `chat.ts`, tool descriptions / parameter descriptions in `tools.ts`, and the results returned to the model plus `error` fields (including the `[Attached file: …]` prefix, `Tool execution failed`, `Unknown tool:`, `The user rejected this write request`). User-visible text (Dialog / Snackbar / bubble status badges / error records / tool card labels) is likewise en-US. **When adding a tool or editing a prompt, never introduce non-English copy** - nothing but English may reach the model or the UI.
15. **Reasoning blocks toggle display modes with icon buttons only - never expand/collapse text buttons**: four modes - `min` (global default, shows only "N characters"; tapping the count opens the full page) / `inline` (full text expanded) / `scroll` (height-limited ScrollView, auto-scrolls to the bottom while streaming) / `full` (tap the icon or the preview to open the `ReasoningFull` full page). The Settings page "Default reasoning display mode" defaults to **min** (`state/settings.ts` `reasoningMode: "min"`).
16. **Tool cards (tool-card): parameters/result/error each occupy exactly one line**: `numberOfLines={1}` + `lineHeight` locks the height (16); **no expand-to-view**; tool cards are interleaved chronologically between text/reasoning parts (see the "tool part ordering" gotcha), and their positions must not shift when generation ends. **Status colors**: `done/running` use `onSurfaceVariant` (the icon already conveys the meaning), `failed/rejected` use `error`; **never use `primary`/`tertiary` as status text colors** (harsh dark blue on light themes, purplish on dark). **Unified card standard (ALL tool cards, including the show_form hub)**: the status indicator (icon + label) always sits on the **right of the title row** (never a second status line); **label vocabulary is fixed, no detail suffixes**: `Pending` (waiting on user approval) / `Running` (working, including tool calls queued for execution - the old show_form "Queued…" is gone, queued = Running) / `Done` / `Failed` / `Rejected` / `Cancelled` (any `user_cancelled` error); a submitted form = plain `Done` (the long "Form submitted · N fields" was removed); **write_file/edit_file `Done` renders the changed line count as the label** (`N lines`, from args `content`/`new_string`; icon unchanged), **download_file `Done` renders the downloaded size** (from result `bytes`, `formatBytes`; icon unchanged); `rejected` renders `close-circle-outline` + error - **the `hand-back-right-off` hand icon is no longer used anywhere** (it made the write card's Rejected look different from every other card's failure states); approval button rows are always **Reject first, affirmative second** (write card [Reject][Approve], form card [Reject][Open], download card [Reject][Open][Approve] - there Open is the middle inspection pill and Approve stays the last affirmative) with the affirmative pill theme-toned (`TagButton` tones: `primary`/`danger` + `neutral` = hollow outline pill reserved for inspection actions like the download Open - never the affirmative fill; `dangerContained` was removed along with the red overwrite Approve), **not** on the left or red. **Result rows are display-stripped of parenthetical details** (`stripParenthetical`) since those details now live in the indicator; the show_form card shows a **`Source:` row** right under the title (`inline` for inline HTML, otherwise the `html_path` file path). **Title-row tap opens the full-screen `ToolDetail` page** (`ui/screens/chat/tool-detail.screen.tsx`, AnswerFull pattern: headerShown:false + own Appbar): a markdown H1+H2/paragraph document of Indicator / Tool call (name/status/call id) / Input (every arg as H3, long values fenced) / Output / Error, en-US copy; **the sole exception** is the pending-confirmation **write** hub card, whose body tap stays the read-only preview dialog (approval flow must not navigate away); the pending download hub card follows the unified behavior - body tap opens the ToolDetail screen carrying the `approvalNote`. **The sole exception for interactivity is the pending-confirmation hub card** (a write_file/edit_file/download_file hit by toolflow pending, whose message is the newest record): the title row + detail rows form an AppPressable (write/edit -> the read-only preview dialog; download -> the ToolDetail screen with the approval note), while the action buttons stand separately outside the row (to prevent double event delivery); a Running download card adds one transient `Progress: <done> / <total>` line (bytes from `toolflow.progress`, re-rendered via the card's own useSnapshot, total shows `?` when the server sent no Content-Length - the row never appears while Pending, since nothing is fetched before approval); errors prefixed `user_cancelled` show "Cancelled" instead of "Failed". **show_form card title**: the model-supplied `title` arg renders **only** in the FormFull Appbar header - the card title row is always just "Show form + status", never concatenated with the form title (long titles crushed the label/status row).
17. **The left side of the input bar is the "+" panel toggle (not an attach button)**: `ChatInputBar`'s `onToggleMore` toggles `ChatScreen`'s `moreVisible`, expanding `InputMorePanel` (`ui/screens/chat/input-more-panel.tsx`, WeChat-style grid: rounded square icons + label underneath, 25% wide, 4 per row; **panel background `theme.colors.surfaceVariant`**, grid icon tiles use `surface` + `outlineVariant` stroke). **Panel height is fixed at a 2-row grid reservation** (`grid minHeight = 90*2`; when the menu has fewer than 2 rows, empty slots serve as placeholders), expanding with a **50ms linear height animation** (`Animated.timing` + `Easing.linear` + `useNativeDriver:false`, triggered after onLayout measures the height); **when the panel is open the toggle icon is a cross (`close`), when closed it is `plus`**. Current items: **Files** -> `navigation.navigate("ProjectFiles")` (import/preview/delete/export zip all live on that page); **Models** -> the same `openModelSwitcher()` as the top-right cog (opens the full-screen ModelPicker). The panel auto-collapses when the keyboard shows (`keyboardDidShow`); tapping "+" first calls `Keyboard.dismiss()`; bottom safe-area padding is held by `inputWrap` (`ChatInputBar` itself no longer consumes `insets`).
18. **Conversation switching lives in the chat page header**: `Appbar.Content`'s `title` takes a ReactElement = conversation name (**truncated to 8 characters**, ellipsized beyond that) + the **rename icon `pencil-outline`** immediately to its right (opens an AppDialog rename, same logic as the Conversations page rename), and the whole row is **horizontally centered in the PageHeader** (`Appbar.Content` style absolutely fills the header + `justifyContent/alignItems:center`; the Paper container ships with `pointerEvents:"box-none"` so the left/right buttons are never blocked); **the conversation-switch entry point is the PageHeader's far-right `Appbar.Action icon="format-list-bulleted"`** (absolutely positioned in a container at the header's right edge, outside the title area); tapping the conversation name or that list icon both open the full-screen `Conversations` page; the ConversationDialog Modal has been deleted. **The sidebar does not show the conversation list** (only projects + entry items). A conversation with an empty name displays as "Untitled conversation" (`ChatStore.create` allows an empty-string title). **The selected Conversations row** = the whole card on `secondaryContainer` background + title/subtitle/icon in `onSecondaryContainer`; leadingIcon is always `book-outline`, selected or not (no "current conversation" label is shown; the subtitle holds only the updated time); row actions = only the three-dot `dots-horizontal` Menu (rename / delete - the per-row "System Prompt" item is gone; the prompt lives on the chat input bar, Key Rule 35), and **rows are wrapped in `AppPressable`: tapping anywhere outside the three dots switches the conversation** (no checkmark icon; the selected state is indicated purely by the `secondaryContainer` highlight). Do not use `primary` as the selected text color. **Row status badges (multi-session WIP)**: inside `cardActions`, to the left of the menu button, render a compact inline badge on demand (Icon 14 + Text 11, the row layout from Rule 20), priority **Needs attention (`bell-ring-outline`, waiting on a write confirmation/form, live) > Error (`close-circle-outline` in error color, last assistant message failed and unread) > Running (`progress-clock`, live)**; no cross-project aggregated hints - after switching projects, check pending items yourself on this page (the conversation list only shows the current project). **Entering a conversation (tapping a row / entering after create / sending) = explicit entry and marks read**; programmatic auto-binding (project-switch landing, cold-start landing) marks nothing read and swallows no badges. Unified list rendering: see Rule 27.
19. **Project files page shows EVERY user entry, dot entries included**: the old dot-entry hiding is gone - `.env`, `.gitignore`, `.github/` and any other `.`-prefixed file/directory are listed / entered / previewed / deleted / renamed / created exactly like ordinary files (a `.env` row opens in FilePreview via `isTextLike`; anything not text-like degrades to the "Unsupported + Open with..." notice, which is intended). The **sole** exception is the reserved `.git`, filtered by `listProjectFiles` at every depth and refused as a New-folder / Rename target - `RESERVED_SEGMENTS` lives in `src/core/paths.ts` and is shared by the file tools and this page (hiding only `.git` also keeps the empty-root `EmptyProjectWizard`, the sole `GitClone` entry point, reachable for a freshly cloned project - and the wizard itself hides **[Git clone]** when the project root already contains `.git`: the list filters that segment out, so an existing repository can look empty; `project-files.screen` probes `exists(<root>/.git)` directly on refresh and passes `hasGit` to the wizard - cloning over an existing repository is never offered). **Actions are centralized in the PageHeader**: the right-side icon buttons, in order, are **New folder** (`folder-plus-outline`, opens a Dialog to enter the folder name, erroring on invalid/duplicate names), **Import** (`plus` - note it is not a download icon), export zip (`export-variant`, first opens a Dialog with an "Include chat history & preferences" checkbox), all via `navigation.setOptions({ headerRight })`; the per-file-row overflow menu (`dots-horizontal`) contains **Rename** (`fs.move`, target inside the current directory, duplicate/invalid name checks) and Delete (directories cascade via `unlinkRecursive`). **Multi-level subdirectory browsing inside the project is supported**: directly below the list sits a breadcrumb bar (`arrow-up` up one level / `Project root` back to root / clickable segment names jump levels / horizontal ScrollView); tapping a directory row enters it; path normalization is centralized in `core/projects.ts` `normalizeProjectRelPath`/`projectDir` (**only the `.` and `..` segments themselves are rejected**, so a path can never climb above the project root - dot names are legal segments now); import/rename/New folder all act only on the current directory and stay locked to the Project scope. **File row tap-to-open rules**: tapping a file row opens the standalone **FilePreview screen** (`ui/screens/projects/file-preview.screen.tsx`, Root Stack, PageHeader title = the file basename **including its extension**, set from route params via `navigation.setOptions({ title: name })` the way `ModelPicker` does it) - a file row never opens externally directly. In-app preview supports **Markdown, TXT and images (`.jpg/.jpeg/.png`)**: md/txt source is split by `splitMarkdownBlocks` (identical block boundaries to the MarkdownBlock parser; long paragraphs/lists chunked) and rendered one block per **FlashList** row through `MarkdownBlock`; images render contain-fitted (native `<Image>`, `onError` -> the read-failure notice). **Code-like files (the rest of the `isTextLike` whitelist - js/ts/tsx/json/yaml/html/py/go/sql/.env/Dockerfile...) are NOT previewed** - the old stacked-`CodeBlock` path is gone: they render the same centered layout as the unknown type with the editable-file icon `file-edit-outline`, the text "This file can be edited here or opened with another app.", and inline **[Edit]** (contained, `pencil-outline`) + **[Open with...]** (outlined) buttons. **Two separate caps, both statOf'd at page entry**: the preview cap **5 MB** (md/txt/images - `readText` loads the whole file into a JS string) vs the **edit cap 512 KB** (the editor is a lightweight tool; over it code-like loses the Edit button - "File too large to edit (over 512 KB)." in the same notice slot - and md/txt hide the menu Edit item; the gate only checks `statOf`, no content is read for the layout). **[Edit] opens the shared TextEditor page** (uncontrolled, validate omitted = default pass): `onSave` = `atomicWriteText` back to the same path + `showToast("Saved")` + goBack, and FilePreview **re-reads on focus return** (Rule 25). **"Text wrap" applies to md/txt only**. Unsupported type / oversized / read failure all show a centered notice + **"Open with..."** button. The header `dots-horizontal` overflow is fixed for every file: for Markdown/TXT a **"Text wrap"** toggle (`MarkdownBlock wrap`, horizontal scroll <-> soft wrap) plus **"Edit"** (`pencil-outline`) when within the edit cap, and **"Open with..."** always - preview never blocks the external path. "Open with..." runs `openFileExternally` (`core/import-export.ts`): the sandbox file is snapshotted into `CacheDir/exports/open_<ts>_<seq>/<name>` (original filename kept as the URI's last path segment), then Android hands it to `ReactNativeBlobUtil.open.file` (`open.file(staged, { mime })` in `core/import-export.ts`: ACTION_VIEW via the library's own `${applicationId}.provider` FileProvider content:// URI + per-URI read-only grant - single handler opens directly, multiple show the system chooser; **no App-owned OpenFile module remains**); iOS and the "no VIEW handler" case (`ENOAPP` / `EUNSPECIFIED`) fall back to `Share.open` with `showAppsToView: true`. **Files over 512 MB are refused** up front (toast "File too large to open (over 512 MB)" - copy-cost/storage-headroom guard). Breaking change accepted (2026-11-15): the old plaintext `secrets.json` was dropped — `load()` deletes any leftover file, and users must re-enter API keys once. The store is in-memory cached after `load()`, so `buildHeaders` stays synchronous (used per streaming request). **The native module cannot enumerate its keys**, so `SecretStore` keeps its own `v1_provider_ids` manifest string. On every `registry.update` / a deleted provider / `importProvidersYaml`, the store calls `rebuild(providerIds)`: it reads each live provider's secret **directly by key** (authoritative), `clear()`s the storage, then re-persists only what belongs to a live provider — guaranteeing **zero orphan secrets** even if the manifest went stale, and treating "provider exists but has no secret" as simply "not configured" (never touched). rebuild is best-effort (never throws / never rolls back a persisted provider change). iOS Keychain has a small per-value size limit, fine for an API key + a few headers.

The same TextEditor serves **System Prompt / Skill content** editing (validate = content non-blank, `contentNotBlank`; onSave writes the registry entry - the conversation-level inline prompt editor moved from this page to the registry, Key Rules 35/36) and FilePreview's **code-like / md-txt file editing** (validate omitted; onSave = `atomicWriteText`, see Rule 19) - cramped dialog textareas are banned for anything longer than a single line.

31. **App-level font size scale (in-memory only, default = the built-in sizes)**: `state/settings.ts` `fontScale` (a numeric preset from `FONT_SCALE_PRESETS` = `[0.9, 1, 1.1, 1.25]`, default **1**) is a pure runtime preference — never persisted to config.yaml / secrets / disk (same convention as auto-approve resets on cold start, Rule 8). It reaches the UI through the derived theme: `useActiveTheme()` bakes the scale into `theme.fonts` (Paper `MD3Typescale`) with a `theme.name:scale`-keyed cache (stable references across renders), so every Paper variant scales for free. Hardcoded point sizes go through **`fs(theme, px)`** (`src/app/app.ui.theme.ts`, returns `Math.max(8, round(px*fontScale))`, identity at scale 1) — this is the single entry point for any Text that must follow the setting; Markdown body/code/tool cards, the chat input, headers, badges, etc. already use it. When adding a raw `fontSize: N` in a `StyleSheet`, override it inline with `fs(theme, N)` at the usage site (or build a per-theme helper like tool-card's `cardFonts(theme)`); never let a new hardcoded size bypass `fs`. **Paper components scale for free** (Appbar / Button / Card.Title / List / TextInput / Menu / Chip / Dialog leaves / Paper `Text variant=...` all read `theme.fonts[...]` from context) - do not wrap them with `fs`. The trap is **raw RN `<Text>` with no explicit size**: it renders at the platform default (14) and never follows the setting - every raw RN Text must carry an explicit `fontSize: fs(theme, N)` (list-empty notices, dialog bodies, section labels, inline badges included); nested RN Text (bold/italic inside a sized parent) inherits correctly and needs no size.

## Key Rules: GitHub Release / CI (Rule 32)

32. **GitHub Release & dotenv source-of-truth (CI/CD)**:

- **Release trigger = git tag** `github-<APP_VERSION>` (e.g. `github-1.0.1`); a GitHub workflow builds the signed APK and auto-generates a GitHub Release with notes.
- **APK name = `<APP_NAME>-<APP_VERSION>-arm64-v8a.apk`** (APP_NAME read from `.env.github` by the release workflow, currently `CafebeeAI`; tag + version consistent → see below). ABI filters **only arm64-v8a** (release package, no x86/x86_64/armeabi-v7a). `ndk { abiFilters "arm64-v8a" }` set on the `github` flavor in `android/app/build.gradle`.
- **Flavors**: dev = `dev` (isDefault, applicationId suffix `.dev`), GitHub release = `github`. dotenv binding rule:
  - Both flavors read identity from `project.env` (populated by `dotenv.gradle`) — **dotenv file is single source of truth** (`ENTRY_FILE`, `APP_ID`, `APP_NAME`, `APP_VERSION`, `APP_VERSION_CODE`, `ENV_NAME`, plus the data-layout keys `DATA_DIR_BASEPATH` / `PROJECT_CONFIG_DIR` / `TOOL_CALL_FORM_BRIDGE_PREFIX` and the two values allowed to diverge among the shared keys, the `APP_DEBUG` page gate (dev 1 / github 0) and `APP_LABEL_SUFFIX` launcher-label suffix (dev `_dev` / github empty) - `APP_LABEL_SUFFIX` is concatenated ONLY into the flavor `app_name` resValue that feeds the manifest `android:label` (the manifest itself keeps `@string/app_name`, no suffix literal); in-app brand, `DEFAULT_SYSTEM_PROMPT`, and git authorName keep following the clean `APP_NAME`; AGP implicit BuildConfig names like `DEBUG` are banned as dotenv keys - see the gotcha entry).
  - `project.ext.envConfigFiles` set BEFORE applying `dotenv.gradle` so the bare-gradlew fallback path works; `ENVFILE` env var (cross-env in npm) still wins.
  - `react-native build-android --tasks=assembleGithubRelease`: task prefix is `bundle` by default (`--tasks` overrides the prefix); we pass `assembleGithubRelease` explicitly for APK.
  - dev flavor keeps `isDefault true` for IDE/debug defaults; github flavor NOT default so `npm run android` stays `devDebug`.
- **Version consistency check** (CI, release workflow): tag `github-X.Y.Z` MUST match `APP_VERSION` in `.env.github`; mismatch hard-fails with "Tag and .env.github APP_VERSION mismatch" + a `sed -i` example.
- **Release message = GitHub auto-generated notes** (workflow uses `gh release create` with defaults).
- **Quality gate** (CI both quick-check and release): `npm run lint && npm run tsc` before packaging.
- **Quick check trigger** (workflow): `push` on `main` + `pull_request` targeting `main`; runs `npm ci && npm run lint && npm run tsc`.
- **Signing strict** (`android/app/build.gradle`): release buildType throws a `GradleException` if `android/key.properties` is absent (prevents local `build:apk` without secrets or debug-signed APK masquerading as a release; CI writes an ephemeral key.properties from GitHub Secrets — never kept in the repo).
- **Key injection in CI** (release workflow): base64-encoded keystore (`ANDROID_KEYSTORE_B64`) + one password for **both** store/key (`ANDROID_KEYSTORE_PASSWORD`, same value) + key alias (`ANDROID_KEY_ALIAS`, the alias created by `keytool -genkeypair` — NOT in the repo, only from GitHub Actions secrets). Materialized by the workflow into `android/app/release.keystore` and an ephemeral `android/key.properties` (the file has 4 lines `storeFile=release.keystore / storePassword / keyAlias / keyPassword`; `storeFile` path resolves relative to `android/app/`). None of these files live in git after CI — only in the runner workspace.
- **`APP_VERSION_CODE`** (Android internal integer versionCode for upgrades): set alongside `APP_VERSION` (semver string shown to users). Both flavors (dev/github) read from dotenv. `about.screen` / `settings.screen` already prefer `Config.*` (BuildConfig via dotenv), JS fallback `src/app/app.constants.ts` stays for no-config dev tools — release identity wins from dotenv.
- **Data-layout keys (brand rename, 2026-11-17; PocketLLM → CafebeeAI = clean break, no migration shims for old installs/old export zips)**: `DATA_DIR_BASEPATH=cafebeeai` (sandbox root `<filesDir>/cafebeeai`, `core/fs.ts` `DATA_DIR_BASEPATH`), `PROJECT_CONFIG_DIR=.cafebeeai` (EXCHANGE-ONLY name: the folder name project state takes inside an export zip (`core/fs.ts`; on disk state lives in `project-meta/<id>/`, never inside a Project) + the `ui/` strip + import routing in `core/import-export.ts`; it is no longer a path segment inside projects - RESERVED_SEGMENTS/gitignore seeding/staticfs deny no longer reference it), `TOOL_CALL_FORM_BRIDGE_PREFIX=__cafebeeai` (`state/formflow.ts` `FORM_BRIDGE_PREFIX` → `llm/form-doc.ts` `buildInjectedScript({bridgePrefix})` window globals). **All three must be identical across `.env.dev` and `.env.github`** (dev/github builds share on-disk layouts; divergent values make the flavors' data mutually unreadable) and **must never be overridden via `.env.*.local`**. config kind is the brand-free literal `v1/config` (`core/config.ts` `CONFIG_DOC_KIND`); other brand-free literals: cache subdir `exports`, Debug fixture `git_demo`, providers export `providers-*.yaml`, `data-form` style marker, GitSdk defensive author fallback `app`/`app@localhost`, SSH key comment fallback `app-android`. The pocket-git package's own identity (`react-native-pocket-git`, java package `com.pocketllm.pocketgit`, codegen) is deliberately NOT renamed (library namespace is brand-independent).
- **Mirror literals of dotenv values (readable ONLY at build/host time, where JS `Config` cannot reach; bump together with the dotenv keys)**: `android/app/build.gradle` (`namespace`/`applicationId`/`build_config_package` + every `?:` flavor fallback), `android/settings.gradle` `rootProject.name`, `strings.xml` `app_name` fallback, `package.json` `name` + `android` script `--appId`, `src/app/app.constants.ts` fallbacks, about-screen APP_ID fallback, `scripts/dev-sandbox-server.ts` defaults (the script parses `.env.github` at startup; the literals are no-file fallbacks), dev-sandbox UI html tokens `__APP_NAME__`/`__SANDBOX_ROOT__` are server-substituted (no literals to sync), Kotlin `MainActivity.getMainComponentName()` + both `src/flavors/*.js` `AppRegistry.registerComponent` (must stay byte-identical to each other).
- **package.json `version` metadata**: kept manually in sync with `.env.github APP_VERSION` at release time (not authoritative). `package.json` is a fallback for toolchain and metadata only; not for `APP_VERSION` — dotenv is authoritative (rule 32).
- **`.env.github` placeholder for `APP_BUILD_AT`**: empty (local `build:apk` shows "-" in UI; release workflow replaces `^APP_BUILD_AT=.*` at runtime so APK timestamp reflects build time, not commit time).
- **Local developer workflow unchanged**: `npm run android` (devDebug) does NOT need key.properties, CI does.

## Key Rules: Static File Server (Rule 33)

33. **Project file serving = `@dr.pogodin/react-native-static-server` (Lighttpd), `src/state/staticfs.ts` + the `StaticFs` screen**: serve the **current Project directory** over HTTP so files can be opened in a browser directly.

- **Single native slot**: the library allows **at most one active Lighttpd server process-wide** (a second launch throws). The product model is one-serves-one-project, so **at most one sidebar wifi light is on at a time**. Starting project B while project A runs = **confirm-steal** (`ConfirmDialog` "Stop the other file server" -> `stopFs()` then start B); no second dialog. Tapping the same screen's `Stop` (own project running) = direct stop.
- **Serve root & privacy**: `fileDir = projectRoot(projectId)`; a Project directory is pure user files (app state lives in `project-meta/`), so **nothing is withheld** - no `mod_access` deny rule remains. Dotfiles (`.env` etc.) stay reachable. **Opening the root URL / any directory in a browser shows a lighttpd directory listing** (files + subdirs) - `dir-listing.activate = "enable"` must be included in `extraConfig`; project directories have no index.html, so without it lighttpd returns 403 at the root (see static-server gotcha).
- **Ports**: always-visible input box (valid domain **1024-65535**) + a **Random** button that fills a JS random port in **49152-65535** (IANA dynamic range; no socket API exists in RN JS, so no availability probe). Invalid/out-of-range and port-in-use both `showNotice` and keep the server off - **never silently fall back to another port** (the copied address would be wrong).
- **Net mode = `nonLocal`**: `local` binds `127.0.0.1`; `any` binds the library's auto-detected non-local IP (origin is only known **after** start, so the Address area appears only while running - **never preview a fake address**). AnyIP shows a persistent "exposed to local network" warning line (library has no `mod_auth`; LAN exposure is unauthenticated by design - only Local default + warning, no token/URL hack).
- **Persistence**: per-project in `project-meta/<id>/config.yaml` (`static_fs: { port, net_mode }`, zod `StaticFsSpecSchema`, same 500ms debounce + `pendingDebounce` merge channel as Rule 8). Missing/invalid port tolerates to a fresh random pre-fill.
- **Lifecycle (explicit-only)**: **no cold-start restore** (exposure never silently renews - the store is in-memory), `stopInBackground: false` (background/screen-off does not stop), switching projects does not stop (light stays on the served project's row). Deleting the served project releases the slot **inside the existing delete confirm** (`stopFsForProject`, no second dialog).
- **Locked while running**: port / Random / net-mode radio are all `disabled` while this project's server is running - the running instance's config is frozen. Editing = stop first (stop-edit-start), so there is no "changed but not applied" ambiguity.
- **UI**: `StaticFs` Root Stack screen (`ui/screens/projects/static-fs.screen.tsx`, `title: "File Server"`, param `{ projectId }`); master row = **`File server` label + right-side compact action `Button`** (no `Switch`) - label reads `Start` when off and `Stop` when running/finishing, `loading +  disabled` during starting/stopping transitions, and mode flips `contained`↔`outlined` per state; **Copy address** = bare `Clipboard.setString(origin)` (**no `showToast("Copied")` - the OS shows its own confirmation**); **Open in browser** = `Linking.openURL(origin)` with a `showNotice` catch. Entry points = sidebar `Drawer.Item right` wifi icon (only on the served project, colored `theme.colors.tertiary` = each theme's green) + the "+" input panel "File Server" tile; both navigate to the screen (row tap still switches project). ## Key Rules: Git Client (Rule 34)

34. **Project git = JGit via the local native package `packages/react-native-pocket-git` (npm `file:` dependency), verbs limited to upload / sync / clone (the app UI renames upload/sync to **Push/Pull**; SDK verbs, payloads and error codes keep their names)**:

## Lessons & Gotchas

- **RN `fetch` has no streaming response body**: SSE streaming must go through XHR. Implementation: `src/llm/openai-client.ts` uses `XMLHttpRequest` reading `responseText` incrementally (`slice(processed)` once readyState>=3). `responseText` is already a decoded string, so the hand-written SSE line parser eats it directly - **no TextDecoder/ReadableStream/TextDecoderStream polyfills of any kind are needed**. **Do not use `react-native-sse`**: it (1) hardcodes `Accept: text/event-stream` / `Cache-Control: no-cache` / `X-Requested-With: XMLHttpRequest` (some gateways reject on these, ending the response immediately with no data); (2) after DONE auto-reconnects every 5s via `_pollAgain` = infinite retry (repeated POSTs mean repeated billing/generation); (3) never dispatches a close event on normal completion -> the stream never closes -> the UI sticks on "Generating…" until the 120s timeout.
- **Request headers align with the POC (`main_fetch_chat_completions.js`)**: send only content-type / authorization / user-defined headers (`kSecretStore().buildHeaders` constructs them uniformly). The hand-written client never sends `accept` / `user-agent` / `cache-control` / `x-requested-with` / `last-event-id` at the source (some gateways reject or misbehave on them); RN XHR does not auto-inject a UA like a browser either.
- **Retry cap (`chat.ts` `runAssistantTurn`)**: `MAX_ATTEMPTS = 3` (including the first attempt). Empty stream / decode errors / network errors / 5xx / 429 / **request-level timeout (LLMIdleTimeoutError)** are all retried (`isRetryableError`); only user stops (AbortError/stopped) and 4xx are never retried. Each retry clears assistant.parts and regenerates, with a 300ms x n backoff. A stopped record persists as `state: "stopped"` + `error: "Interrupted by user"`, and the bubble shows "⚠ Interrupted by user" in error styling.
- **Metro/babel need no special configuration (one documented exception, see the zod entry)**: `metro.config.js` / `babel.config.js` stay at RN defaults - never add polyfill/transform/resolver hacks to paper over bundling problems, root-cause them first. The single sanctioned plugin beyond `react-native-worklets/plugin` is `@babel/plugin-transform-export-namespace-from` (7.x line - the 8.x line demands `@babel/core@^8`), required by zod v4's ESM build.
- **FlashList v2 has no `estimatedItemSize`**: v2 measures heights automatically; also don't take a v1-style one-way dependency; for reversed lists use `data={[...].reverse()}` + `inverted`.
- **SSE wire format (gotcha for the hand-written parser)**: the cut points of XHR `slice(processed)` are unrelated to line boundaries, so you must maintain a **line-tail cache** (`feedSSE` returns the rest for splicing on the next round); process only lines starting with `data:`; `[DONE]` is the termination sentinel; comment/keep-alive/non-JSON lines are ignored outright (parse failures must not throw).
- **Programmatic mid-string draft replacement (skill expansion) rides the same controlled-value path as the send clear**: `expandSkillsOnEdit` rewrites the draft through `entry.draft`/`draftStore` - the same programmatic value-mutation channel documented in the auto-grow gotcha (Android may place the caret at the text end after such a write; acceptable because replacement only fires at token terminators and the send-time full sweep guarantees the final content regardless of what the box showed mid-typing). The in-place splice must stay single-pass over the pre-expansion text (the changed-region terminator rule), otherwise an inserted skill body containing another `/name` would cascade-expand recursively; the only place previously inserted bodies expand again is the send sweep on the message copy, which the user then sees verbatim in the bubble - deliberate, do not "fix" (rule 36).
- **tool_calls streaming aggregation**: `delta.tool_calls[]` aggregate by `index` - the first chunk carries `id` + `function.name`, and `function.arguments` concatenate piece by piece (**mid-stream it is incomplete JSON and must not be parsed early**; parse as a whole only after the stream ends); reasoning comes from `delta.reasoning_content` (also tolerate `delta.reasoning`). Multi-step loop cap `MAX_STEPS = 15` (`chat.ts`, because search/edit tool chains take many steps); exhausting the steps counts as completion.
- **Streaming fallback (prevents the UI from sticking on "Generating…")**: **timeouts only bite HTTP requests, never the flow** - the watchdog was pushed down into openai-client as a request-level `idleTimeout` (default 120s; each `resetIdle` fires on received bytes; when it triggers, call `fail(LLMIdleTimeoutError)` first and only then `xhr.abort()` - the order must not be reversed, to prevent AbortError/network errors from pre-empting the settle into the wrong error classification). LLMIdleTimeoutError is classified as a retryable network error and goes through `MAX_ATTEMPTS`; tool execution / card confirmations / form waits have no timers whatsoever (waiting on a human is legitimate, even overnight); the turn-orchestration layer sets no watchdog and you must not re-add a "form extension" special case (deleted along with the turn-level watchdogs). `turnHandle(projectId, convId)` generation counters prevent stale turns in the **same session** from overwriting state; turns in different sessions never interfere. Non-2xx HTTP lands in `LLMHttpError.status` (408/429/5xx retryable, other 4xx not retryable); an empty stream (no parseable chunk and no content) throws "empty response" into the capped retries.
- **zod is used only for `config.yaml` and the Providers YAML transfer** (^4.6; upgraded from ^3.25 on 2026-11-19 to clear GHSA-mrhx-c7xc-m3w5 — the migration touched **zero `src/` lines**: this repo's surface (z.object/string/.trim/.regex/.min/.max, z.number().int(), z.enum, z.literal, z.array().max, .optional, .safeParse, z.infer, `error.issues[0].path/.message`) is fully v4-compatible; only remember string shorthand error params like `.min(1, "msg")` are deprecated-but-working (use `{ error: "..." }` when touching them) and `z.number().int()` now rejects unsafe integers). **zod v4's ESM build uses `export * as ns from ...` and breaks Metro without `@babel/plugin-transform-export-namespace-from` in `babel.config.js` plugins** (error: "Export namespace should be first transformed by ..."; the plugin runs in the plugins phase before the RN preset's `transform-modules-commonjs`, and it must stay on the 7.x line while `@babel/core` is 7.x - see the Metro/babel gotcha); tool parameter schemas are now hand-written JSON Schema and no longer converted through zod.
- **`react-native-encrypted-storage` limits (SecretStore's shape)**: (1) no `getAll`/key enumeration - so SecretStore keeps its own `v1_provider_ids` manifest; (2) `clear()` is the only way to guarantee an orphan-free sweep; (3) **iOS Keychain value size limit (~2 KB per value)**: acceptable for one API key + a few headers, but oversized values fail silently and return null on the next read; the payload should only hold `{ apiKey, headers }` - if large secret values are ever added (long PEMs / JWTs), store a hash reference and keep the data in an app-generated AES encrypted blob in EncryptedStorage instead. (4) iOS `EncryptedStorage` stores under default-access Keychain; no biometric constraint. (5) The library is a **bridge module**; with new architecture (this repo uses newArch on iOS + Android) native modules must be TurboModules - `react-native-encrypted-storage` 4.0.3 still works via RN auto-bridge (no codegen on this target). If new-arch build breaks, swap `@sayem314/react-native-keystore`; do **not** write your own native module.
- Exports go through the **share sheet**, not "pick a target directory" (iOS has no generic directory-picker API).
- `@react-native-documents/picker` returns `content://` on Android: you must first call `keepLocalCopy({ destination: "cachesDirectory" })` to obtain a local path, then copy it into the project.
- **Android cannot share/open `file://` URIs from the sandbox**: since API 24 a raw `file://` cross-app URI is a hard no (FileUriExposedException); react-native-share resolves local paths through `FileProvider.getUriForFile`, but its bundled provider (`rnshare.fileprovider`: external `Download/` + cache) and blob-util's provider (`${applicationId}.provider`, `provider_paths.xml`: external/files/cache) cover **nothing under internal `filesDir`** - `getUriForFile` throws, `compatUriFromFile` swallows it and hands back null, and the share silently does nothing (this was the "tap an image, no reaction" bug). External open therefore stages a **cache snapshot** (cache-path is covered by every provider config) instead of exposing `filesDir` or adding `files-path`; same reason export zips always write to cache first. The App no longer ships its own FileProvider/`file_paths.xml` (removed with `OpenFileModule`; external open goes through blob-util `open.file`).
- **MIME via `mrmime` + override table, never `mime-types`**: `mime-types@3` does `require('path')` at module top - Metro resolves no Node builtins and the only fix is a metro shim, which the repo bans ("metro.config.js back to RN defaults"). `mrmime` (tiny, zero deps, dual CJS/ESM) builds from mime-db but strips `vnd.*`/`x-*` types (office/media vanish) and maps `.ts` to `video/mp2t` (MPEG transport stream, not TypeScript). Hence `mimeForFile` order: own `MIME_TYPES` override -> `isTextLike` -> `text/plain` -> `mrmime` -> `application/octet-stream`; keep the override table, do not "let the library handle everything".
- **ACTION_VIEW needs manifest `<queries>` on targetSdk 30+**: without `<queries><intent><action android:name="android.intent.action.VIEW"/><data android:mimeType="*/*"/></intent></queries>`, package visibility hides every viewer app from intent resolution (blob-util `open.file` → `startActivity`) and each open falsely fails with `ENOAPP` / "No app can open this file type" (broad `*/*` queries would need Google Play justification; this app sideloads).
- **Staged open snapshots are TTL-only**: the receiving app often reads the granted content URI after `Share.open`/the chooser resolves (a Drive/backup upload runs in its own process, minutes later) - never unlink the staged file right after sharing; `sweepShareCache()` deletes entries older than 24h, fire-and-forget at `kApp` bootstrap + ahead of cache writes. The 512 MB open cap doubles as the guard that keeps the copy step from stalling the open action or exhausting storage.
- **valtio `useSnapshot` is readonly**: before writing a snapshot array back into the proxy (e.g. `entry.messages = next`), deep-copy it (`map((m)=>({...m, parts:[...m.parts]}))`); remember to clone when writing logs/tool cards. **Snapshot objects are equally unwritable** - "clearing state" like `sessionSnap.error = null` must go through `getEntry()` to write the raw proxy (ErrorRecordBar's removeError tripped on exactly this).
- **Streaming updates must swap item references (valtio + FlashList)**: `assistant` is a raw object and stream mutations bypass the proxy; valtio caches snapshots by raw reference + FlashList memoizes cells by item identity => merely doing `messages=[...messages]` (item references unchanged) means the UI never refreshes (stuck on "Generating…", incremental text invisible). `flushUI` / turn finalization in `chat.ts` use `replaceAssistant` (clone a new object from raw to replace the same-id item).
- **blob-util `mv` is not atomic and a fixed tmp name causes collisions**: `mv` is implemented as "check src exists -> delete dest -> renameTo"; two concurrent `atomicWriteText` calls on the same file (e.g. a debounced preference flush colliding with a rename, or consecutive saves in one session) report `ENOENT: Source file at path ...tmp does not exist`. Fixed in `src/core/fs.ts`: serialized write queue per path + unique tmp names (`.tmp-<ts>-<seq>`) + fallback to writing the destination directly when mv fails; `kApp().ready` never rejects (caught inside bootstrap), and UI action handlers wrap try/catch + problem-notice dialog.
- **react-native-blob-util streaming download (the download_file mechanism and its traps)**: `ReactNativeBlobUtil.config({ path, overwrite: true, followRedirect: true }).fetch("GET", url)` streams the response body natively into that file (response `type === "path"`, zero JS memory - that is what makes the 50MB cap safe); a non-2xx response **resolves normally** (check `res.ok`/`res.status` and discard the staged body - an error page must never land in the Project); `cancel()` rejects the promise (`CanceledFetchError`), so the caller must keep its own aborted/stalled/cap flags and map the rejection to the right error string; **the `timeout` config bounds connect/write only - for a download to a file the native side deliberately sets the read timeout to 0** (the 60s default used to kill slow large files), so stall detection lives JS-side: a 300s timer re-armed by every `progress(received, total)` tick, firing `cancel()`; the size gate is a Content-Length pre-check (`stateChange` headers; the map is lower-cased on Android, mixed elsewhere - check both) + the `progress` received counter (authoritative) + a final stat re-check before the move; `moveInto()` ensures the destination parent dir and falls back to cp+unlink when the cross-directory rename fails; staging lives in `CacheDir/exports/` via `stageDownloadTmp()` (sweepShareCache runs first like every cache-write entry point, crash-orphans age out through the 24h TTL sweep); transfer progress is transient `toolflow.progress` state (toolCallId -> {received, total}, cleared when the tool settles, never persisted) read through the card's own `useSnapshot` subscription - it does not ride the messages flush pipeline.
- **yieldable-json's three hard constraints (message-file encoding, `core/async-json.ts`)**: (1) **only `stringifyAsync`** - `parseAsync` touches `Buffer.isBuffer` at entry and Hermes has no `Buffer` global (also native parse is faster), so decoding stays on `JSON.parse`; (2) **never run two encodes concurrently** - the library keeps module-level mutable state (`counter`/`temp`/`objStack`), interleaved runs corrupt each other (false "Circular Structure Detected" / broken escapes); `stringifyAsyncSafe` strictly serializes through a promise chain; (3) **the encoded object must not mutate mid-run** (README) - `persistNow` therefore hands in `valtio snapshot(...)` (immutable plain tree, cached; the raw streaming message mutated in place between flushes is invisible to it) instead of the live proxy, and `saveMessages` no longer writes `updatedAt` onto the input object - it spreads `{...conversation, updatedAt}` (valtio 2.x derived snapshots are plain objects, NOT frozen - verified empirically; they are only ever mutated by rebuild, never in place). The snapshot persisted at flush N may lag the raw text of in-flight deltas - that is intended (last-write-wins per file; turn end forces a final `persistNow` after the closing `replaceAssistant`).
- **`openModelPicker` drives navigation from outside a component**: `state/modelpicker.ts` **must not** import `app.ui.navigator` (`navigator -> chat.screen -> llm/chat -> modelpicker` would form a runtime cycle). By convention, `app.ui.navigator.tsx` calls `bindModelPickerNavigator(fn)` at module load to register in reverse; when `fn` returns `false` (navigation not ready), `openModelPicker` immediately calls `closeModelPicker(null)` so the send flow never hangs forever. `ModelPickerScreen` also falls back to `closeModelPicker(null)` on unmount if nothing was chosen (hardware back / swipe).
- Paper v5 Dialog has no `scrollable` prop; full-text previews use `AppDialog.ScrollArea`; confirmations always use `AppDialog`+`Button` (`Alert` is banned).
- **Paper `Dialog`/`Modal` render incorrectly under the new architecture (Fabric / RN 0.85)**: their `Surface` force-appends `elevation` on Android (Dialog additionally carries the old-architecture shadow-clipping workaround `elevation: 24 + marginVertical: 44`), and open/close animates `opacity` with `useNativeDriver: true` - once "elevation + native opacity animation" is promoted to a hardware layer, **the card background stops drawing (only the scrim remains) and the elevation shadow lingers as a dirty block**; additionally, Dialog expects callers to wrap `Portal` manually, and without it the positioning follows the local screen tree. The centralized fix: **`AppDialog` in `src/ui/components/app-dialog.tsx`** - it always wraps `Portal` internally, the card is a plain View with an explicit solid `elevation.level3` background (`borderRadius: 7`, no `elevation`/shadow at all), and fade in/out runs through the JS driver; `Title/Content/Actions/ScrollArea/Icon` directly re-export Paper's leaf subcomponents, so the API matches the original Dialog (`dialogCompact`/`dialogLiftStyle`/`useModalInputFocus` all keep working). **Card width convention: the card takes `width: "100%"`, and horizontal whitespace goes on the wrapper's `paddingHorizontal`** - inside an `alignItems:center` shell, a card without an explicit width (relying only on maxWidth/content sizing) lets TextInput shrink-wrap at infinite width, making dialogs both narrow and tall; **do not add `marginHorizontal` to cards anymore**. Do not introduce any new Paper Dialog/Modal usage.
- **This repo's Paper 5.15.4 has no `Dialog.contentPadding` prop (a newer API - misusing it breaks tsc), and `RadioButton.Item` has no `dense`**: compaction always goes through subcomponent `style` overrides (centralized as `dialogCompact.title/content/scrollArea/actions` in `src/ui/components/dialog-compact.ts`), or pass `style={{ paddingVertical }}` to RadioButton.Item.
- **Compact style convention**: list-page contentContainer padding 12, card marginVertical 4, dialog horizontal whitespace 16 (`dialogCompact`), `Dialog.Actions` minHeight 40, dialog action buttons uniformly go through **`DialogButton`** (`ui/components/dialog-button.tsx`: built-in `compact` + radius 20 -> 17 (16% less round) + content paddingHorizontal 20 widened, vertical padding untouched - no raw `<Button compact>` inside dialog actions), `TextInput` uniformly `dense`, `dialogLiftStyle` carries `maxWidth: 340`. Radio/checkbox option rows never ship a bare dot + label pair again: **use `RadioRow` / `CheckRow`** (`ui/components/option-row.tsx`) - the whole row is one AppPressable responder and the Paper control rides along with `pointerEvents:"none"`, fixing "only the checker responds" taps. The ChatScreen input bar replicates the MD3 **filled** style (`surfaceVariant` fill + `borderRadius: 4`, **no bottom indicator line / focus underline**, not outlined).
- `yaml` (@2.9) is isomorphic pure JS, usable directly under Metro; config deserialization failures always return an empty preference object.
- `react-native-vector-icons` Android fonts are handled by `fonts.gradle` in `android/app/build.gradle`; Paper internally uses MaterialCommunityIcons.
- uuid generation: no dependency on native crypto; `uuid.ts` ships its own implementation (lowercase, dashes stripped).
- blob-util's `stat().type` is only ever `'file' | 'directory' | 'asset'`; for binary file I/O, `readFile(path,'ascii')` / `writeFile(path, number[], 'ascii')` is the most reliable (raw bytes).
- **tool part ordering (fixes "toolcall cards jump position around the end of generation")**: early on, `syncToolParts()` in `chat.ts` re-collected all tool cards after every text/reasoning part, and reordered only once at stream end => cards interleaved with text during streaming, then slid down wholesale afterwards. Current convention: `ensureToolPart()` pushes into `assistant.parts` in arrival order; the `toolParts` map holds the same reference and mutates args/status/result in place, and flush shallow-clones it out; any change to parts ordering must guarantee **streaming and final order are identical**.
- **FlashList inverted pushes the scrollbar to the left**: v2 implements `inverted` by mirroring the whole list on the X axis (Android `scaleX:-1`, iOS a 180-degree rotation), so the inner ScrollView's native scrollbar mirrors to the left too. The fix: `renderScrollComponent` passes a module-level component that applies another `scaleX:-1` to the ScrollView itself, pulling the scrollbar back to the right, while each cell's content is wrapped in an equal counter-mirror (`chat.screen` `styles.cellMirror`). Note `renderScrollComponent` **must be a module-level constant** - an inline function changes the component type on every render and rebuilds the ScrollView.
- **Streaming jank (localized rendering, three tiers)**: streaming floods the JS thread if the whole ChatScreen rebuilds per flush. The fix has three tiers, all required: **(1) shell isolation** - ChatScreen never reads `entry.messages`/`entry.draft` (valtio `isChanged` on the affected path fires on `flushUI`'s `entry.messages =` write otherwise, re-rendering Appbar/modelBar/StreamIndicator/ChatInputBar + inline `onSend/onToggleMore` identities every flush); the list lives in `MessageList` FC (`ui/screens/chat/message-list.tsx`) keyed by `boundSessionKey`, and draft lives in the `draftStore` low-frequency slice subscribed by `ChatInputBar`. **(2) update coalescing** - `MessageList` uses `useSnapshotCustom` (`ui/use-snapshot-custom.ts`: `subscribe` + debounce 150/maxWait 300 + leading when idle + `flushNow()` bypass for non-streaming writes), **never plain `useSnapshot(chatSessions)` for messages** (60ms proxy gate would repaint the list at 16fps, and each repaint re-parses the whole accumulated markdown - O(n²) over a long reply). **(3) cell-level stability** - FlashList v2's ViewHolder `React.memo` compares **the renderItem function identity**: per-turn scalars (`lastAssistantId`/`streaming`/`humanWait`) go to cells through `CellFlagsContext`, so renderItem is `useCallback([])` FOREVER and only context flips repaint cells; `callbacks` built once via useMemo with handlers fetching fresh from raw `getEntry()` inside; never clone all messages in ChatScreen (unchanged snapshot items keep stable refs and skip via the comparator; `dataForList` reverse is memoized on the messages reference). Typing consistency: the draft subscription MUST pass `{sync:true}` (valtio's default notify is microtask-batched - fast keystrokes can render a stale snapshot).
- **Multi-session registry concurrency guards**: the entry object identity is the only gate against "delayed write-back" - `persistNow` first verifies `entries.get(key)===entry` before writing (prevents deleted/evicted sessions from resurrecting); LRU eviction must **re-check `isWip`** after awaiting the flush before dropping (the user may have reopened that session during the flush); deleting a conversation goes through `releaseConversation` (seq++ makes old turns' finalization blocks skip wholesale) - aborting without invalidating leaves a stale write path.
- **Confirmation/form bridges are scoped per session**: `cancelFormsFor/cancelWriteConfirmationsFor(projectId, convId)` - stop/preempt/delete clear only that session; **never revert to the global cancelAll\*** (with parallel sessions it would wrongly kill other sessions' pending cards). When preempting, abort first then cancel: `withAbortRace`'s abort listener settles to 'aborted' first, so the confirmation promise's later-arriving `false` is swallowed - the card's terminal state comes from `markInterruptedTools` (user_cancelled) and is never mislabeled as "user rejected".
- **Read marks only record terminal-state assistant message ids**: a streaming message can also be caught by "entering a conversation"; if a non-terminal id were recorded in `lastReadId`, then when background finalization later failed (same id) the badge would never light up (the reminder would be lost); always fetch the value through `lastTerminalAssistantId()`.
- **AppPressable must not nest a Paper Button**: if the pending card's "tap body for preview + inline approve/reject" were built as one pressable card containing the buttons, parent/child gestures fight (RN's responder favors the child, but double-delivery/event-swallowing is unreliable across devices) - keep the preview touch area and the button row **side by side as layers**, with the buttons independent outside.
- **AppPressable's style prop is a NON-interactive frame**: the outer View (style side) never hit-tests - only the inner Pressable, which wraps `children`, receives touches. Putting the tappable element's size as `style=` while the sole child is a small Text shrinks the touch area to the glyph (the roundel 'hard to tap' bug). A fixed-size tap target must pass its sized View as a CHILD; hitSlop only pads that child's box. For the input-bar prompt roundel: `<AppPressable hitSlop={8}><View badge><Text initial/></View></AppPressable>`.
- **High-frequency UI state gets its own small file**: drafts/read marks go to `project-meta/<id>/ui/conversation_<convId>.json` (800ms debounce, never in the export zip, never in the chat history file); deleting a conversation cascades `removeUiState`; deleting a project drops `dropProjectUiStates` (in memory).
- **ChatScreen auto-binding paths = not explicit user entry**: project-switch landings, cold-start landings, and post-delete fallbacks all use `markRead:false`, and after `await list/create` but before `bindConversation` you must re-check `runtime.currentProjectId` (a project-switch race could re-bind the old project's conversation and swallow its badges).
- **"streaming" means a turn in flight, not "Generating…"**: while waiting for human approval (pending card / pending form), `entry.streaming` stays true and the message `state` stays `"streaming"` - that is the data basis for preemption/stop gating, LRU pinning, and the list's fallback "Running" badge, and **it must not be changed for display purposes**; the display layer must branch on `humanWait`/`waitingHuman`: while waiting, the bubble shows "Reply complete" (footer rendered, no "Generating…" badge) and the input bar keeps the send icon - never map streaming to "Generating…" UI in one shot.
- **Keyboard avoidance is centralized in `src/ui/use-keyboard-lift.ts`**: `useKeyboardLift()` returns the keyboard height only on Android API 35+ (adjustResize stops working under edge-to-edge) and always 0 otherwise (lower versions still use native adjustResize / iOS uses KeyboardAvoidingView or `automaticallyAdjustKeyboardInsets`). Centered Dialog/Modal apply `dialogLiftStyle(lift)` (translateY -lift/2 is enough to clear the keyboard); bottom-anchored input rows simply add lift to `marginBottom/paddingBottom`. Any new page with an input must adopt this set - no scattered Keyboard listeners.
- **Paper `TextInput` (outlined) hardcodes `minHeight: 56` internally even without a label** (the labelContainer in v5.15 `TextInputOutlined.tsx`; `dense` only brings it to 48, and no prop overrides it - passing `style.height` freezes multiline auto-grow) => the input box floats ~17px taller vertically than the padding defined by `contentStyle`; on top of that, Android's native multiline TextInput applies `includeFontPadding` by default, padding the text a few more px. The chat input bar therefore switched to a **native TextInput + absolutely-positioned bordered View replicating MD3 outlined** (`chat-input-bar.tsx`: 1px `outline` / 2px `primary` on focus, `includeFontPadding:false`, `textAlignVertical:"top"`, all colors from `useTheme`). Auto-grow works by measuring the content height in `onContentSizeChange` and then explicitly setting `height` to `clamp(single-line height, 120)`: **never give a multiline TextInput `flex:1/flexGrow`** (flexBasis:0 stops EditText from growing with content, so line wraps do not raise the height; past `maxHeight` it scrolls internally). Follow this recipe whenever you need a compact multiline input - don't force Paper's props. **Never let a programmatic `value` clear/swap trust `onContentSizeChange` to shrink the box** (Android): the clear path (`ReactEditText.maybeSetText` empty -> `TextView.setText` -> `checkForRelayout` -> `nullLayouts`) leaves the size watcher measuring the stale JS-pinned view height and its dedup swallows the event, so the empty input keeps the previous content's line count (the "empty box stays 2 lines after send" bug). JS must reset the measured height itself whenever the text becomes empty or the draft is replaced programmatically (see `chat-input-bar.tsx` effects on `value`/`draftKey`).
- **`react-native build-android --mode=X` produces an AAB, not an APK**: the CLI's `buildAndroid` command hardcodes the gradle task prefix `bundle`, and `bundle<Variant>` is AGP's Android App Bundle task. To emit the classic APK, pass `--tasks=assemble<Variant>` explicitly so `getTaskNames` returns `app:assembleGithubRelease` — this is what `npm run build:apk` does. The output lands at `android/app/build/outputs/apk/github/release/app-github-release.apk`.
- **react-native-config parses ONE dotenv per gradle invocation** (single-variant-per-command rule): `dotenv.gradle` runs `loadDotEnv()` once and caches `project.env` before android{} evaluates; it cannot feed different env files to different flavors in the same task graph, and `ENTRY_FILE` defaults to a non-existent `index.js` when the env file is not resolved, breaking non-debuggable `assemble<Flavor>Release` variants. Building both `dev` and `github` or running `assemble` (which builds ALL flavors) will fail with a mismatched `ENTRY_FILE` and wrong `applicationId`.
- **`@dr.pogodin/react-native-static-server` orphan server across JS restart**: the native Lighttpd process is NOT tied to the JS module lifecycle. If Metro reloads (or fast-refresh remounts `staticfs.ts`) while a server is `ACTIVE`, `server` resets to null in the new JS context but the native slot stays occupied, so the next `new Server().start()` throws "server already active". `startFs` therefore always calls `getActiveServerId()` first and, if non-null, reattaches with `new StaticServer({ id, state: STATES.ACTIVE, fileDir })` + `.stop()` to reclaim the slot before launching (the library's documented reconnect procedure). The Server instance is held at module scope (it is not serializable, so it is not in the valtio proxy).
- **static-server peer `@dr.pogodin/react-native-fs` is a hard runtime dep AND must be a direct `package.json` dependency**: `index.js` imports `DocumentDirectoryPath`/`mkdir`/`copyFileAssets` from it at module load, so npm auto-installs it and autolinking must resolve its native module too (do not attempt to strip it as "unused"). **The catch**: RN's autolinker (`react-native config` + gradle `generateAutolinkingPackageList`) scans only the app's direct `dependencies`, never peer/hoisted packages - npm resolving `@dr.pogodin/react-native-fs@2.x` under `node_modules` at the top level is _not_ enough; without the direct entry it never reaches `PackageList.java`. Symptom of missing it: on the first `new StaticServer(...)` the app crashes in JS with `TurboModuleRegistry.getEnforcing(...): 'ReactNativeStaticServer' was not found` (or after that, `'ReactNativeFs'`), because the static-server spec is loaded at index.tsx module-eval time and the RNFS native spec sits behind it. Fix = keep both `@dr.pogodin/react-native-static-server` **and** `@dr.pogodin/react-native-fs` in `package.json` `dependencies`, then rebuild (the `:app:generateAutolinkingPackageList` gradle task re-emits `PackageList.java` whenever `package.json` inputs change; a stale file on disk is what hid the fix). **Version pin**: `@dr.pogodin/react-native-fs` must stay `~2.40.4` (last version before the spec started using codegen's `ArrayBuffer` type at 2.41.0) - RN 0.85.3 codegen rejects `ArrayBuffer` (`UnsupportedGenericParserError: Unrecognized generic type 'ArrayBuffer'`) because that support landed with RN 0.88's codegen. A naive `^2.40.x` caret or plain `latest` silently upgrades through 2.41.0 and breaks build; the static-server peer range is only `>= 2.22.0` so tilde-pin is safe. Bump to `^2.41.0` only alongside the whole RN 0.88 upgrade (which brings codegen's ArrayBuffer support). Directory listing (`mod_dirlisting`) is a default-loaded core module, but this build's `defaults.dir_listing = 0` (lighttpd `mod_dirlisting.c` set_defaults + `if (!pconf.dir_listing) return HANDLER_GO_ON`) - so the bare config yields **403 Forbidden** at directory URLs (project dirs have no index.html for mod_indexfile to fall back on). `dir-listing.activate = "enable"` **must** go into `extraConfig` (the old `mod_access` `.cafebeeai` deny is gone - app state no longer lives under the served root).

The debug-page gate therefore uses `APP_DEBUG` (1 in `.env.dev` / 0 in `.env.github` - the key exists in both, the value may diverge), consumed as `Config.APP_DEBUG === "1"` in `settings.screen`; never name a dotenv key `DEBUG` (or `RELEASE`/`BUILD_TYPE`/`FLAVOR`/`VERSION_*`/`APPLICATION_ID`).

## App-level singletons + lazyInit (convention)

All App-level stateful objects uniformly use `singleton + lazyInit` (`src/core/lazy.ts`, `k` prefix naming, call shape `kXxx()`):

- `kApp` (src/app/app.ts) - startup bootstrap, `kApp().ready`
- `kLightTheme` / `kNewsprintTheme` / `kDarkTheme` (app.ui.theme.ts)
- `kScreenNavigator` / `kDrawerNavigator` / `kNavigationRef` (app.ui.navigator.tsx) - all navigators are defined globally; inside components use `const Stack = kScreenNavigator()`
- `kChatStore` / `kProviderRegistry` / `kSecretStore` / `kSystemPromptStore` / `kSkillStore` (core storage layer / global registries)

Note: use `lazyInit` from `src/core/lazy.ts`. valtio store proxies (`runtime`/`settings`/`chatSessions`, ...) stay directly exported and are not wrapped in lazyInit.

## Theme & Navigation Conventions

- `NavigationContainer` must be given a `theme` (`useNavigationTheme()`, derived from the Paper theme), otherwise native headers/page backgrounds do not follow light/dark.
- `kNavigationRef()` is the global container ref: use it to drive navigation/drawer from outside components (`openHomeDrawer()` / `closeHomeDrawer()`); buttons inside drawer sub-screens dispatch `navigation.dispatch(DrawerActions.openDrawer())` directly.
- Never use `navigation.getParent()?.dispatch(DrawerActions.openDrawer())`: native-stack parents do not handle `OPEN_DRAWER`, and it throws "OPEN_DRAWER was not handled by any navigator".
- UI must **never hardcode colors** (gray text like `#9ca3af`, `#ef4444`, `#fff`, or "fixed dark code block" patterns); always `useTheme().colors` (secondary text `onSurfaceVariant`, danger `error`/`onError`, accent `primary`/`onPrimary`, block-level fills `surfaceVariant`/`elevation.levelN`); the three theme objects are reused stably via `kLightTheme/kNewsprintTheme/kDarkTheme`.
- **Pick tokens by "fill or text" - two token sets (never primary for everything)**: `primary`/`onPrimary` only for genuinely interactive controls and selected states (cursor, selection stroke, FAB, active icon); **explanatory/status text** uses `onSurface` (emphasis, section titles) or `onSurfaceVariant` (secondary, "done/running" status) - **do not use `primary`/`tertiary` as text color** (harsh dark blue on light themes, purplish tertiary on dark); **filled backgrounds** use `surfaceVariant` (tiled blocks: tool cards / reasoning blocks / inline code chips / the "+" panel / breadcrumb bar / badges) or `elevation.levelN` (floating surfaces: code blocks / Appbar / Chip); **emphatic backgrounds** use `primaryContainer`/`secondaryContainer` paired with `onPrimaryContainer`/`onSecondaryContainer` (user bubbles; selected conversation-list rows are a full-row `secondaryContainer` pill + text/icon in `onSecondaryContainer`).
- **MD3's default tokens are purple-tinted; the whole set must be rewritten**: Paper's `primaryContainer #EADDFF / secondaryContainer #E8DEF8 / surfaceVariant #E7E0EC / background #FFFBFE / elevation.level1~5` are all purple-leaning neutrals; overriding only the `primary/secondary/tertiary` hues accomplishes nothing (Drawer.Item selection, SegmentedButtons selection, Chip, Snackbar, and user bubbles all consume container/elevation tokens). Centralized in `app.ui.theme.ts`: each theme ships a **frozen full-token block** (`NEWS_PRINT_COLORS` / `LIGHT_COLORS` / `DARK_COLORS`) that replaces `colors` wholesale - never hand-write a one-off token, and never let anything fall back to a Paper default.
- **Theme mode is an App-level enum `ThemeMode = "system" | "newsprint" | "light" | "dark"` (`state/settings.ts`, default `newsprint`)**: resolution is centralized in `resolveThemeName(mode, systemScheme)` - under `system`, system dark -> `dark`, system light -> `newsprint` (eye-friendly warm white takes priority over pure white); adding a theme value means changing only this function + the Theme `RadioButton.Group` list in `settings.screen` (the old SegmentedButtons capsules were replaced with radio rows), never scattered conditionals in pages.
- **Palette generation convention**: the hex blocks were produced by the (now-removed) seed engine - `SchemeSpec = { dark, surface, primary, secondary, tertiary, error, neutral, neutralVariant }` hue/chroma seeds + `LIGHT_TONES`/`DARK_TONES` nominal tones (`accent 0.36/0.72`, `container 0.78/0.28`, `onContainer 0.16/0.9`) via `hslToHex`/`mixHex`, with per-hue floors (accent vs its `on` >= 5:1; container vs background >= 1.4:1 and strictly more chroma than `surfaceVariant`; drift <= 0.05); `surfaceVariant/onSurfaceVariant/outline/outlineVariant/inverse*` follow the neutral ramp; `elevation.level1~5 = mix(surface, primary, light 4%~14% / dark 10%~30%)`. To change any token, rebuild the pipeline offline (`node`), evaluate once, paste the hex back - **never eyeball a hex into a block**. Three themes: **newsprint** warm h36 (amber-brown primary, muted amber-brown secondary h35 - never terracotta/rose: an h18 low-chroma container has `r-g > g-b` and reads pink/purple on cream, so secondaryContainer #d2c2bb→#d0c8be; olive-green tertiary, brick-red error, base `#F5F0E6`); **light** cool gray-blue h214 (base `#FBFBFD`); **dark** cool-blue high-key (light steel-blue primary, deep-indigo container, base `#121316`). Adding a theme = adding a frozen block.
- **Each theme's container/neutral tokens follow their own hue - never reused across themes**: on newsprint, user bubbles and selected rows are warm sand (`primaryContainer ≈ #D8CAB6` + `onPrimaryContainer ≈ #382C19`), **not blue**; light is cool gray-blue, dark is deep indigo. Containers must be more saturated than `surfaceVariant` (>=1.4:1 against the background with a distinguishable hue), otherwise emphatic blocks and tiled blocks are indistinguishable; the neutral ramps (`neutral`/`neutralVariant`) also carry the theme hue, otherwise `surfaceVariant`/borders retain MD3 purple-gray that clashes with the warm white (table headers / tool cards / reasoning blocks / inline code chips / code blocks blur into one another).
- Code blocks (`code-block.tsx`) **follow the theme's surface level**: body `elevation.level2` + header `elevation.level3` + hairline `outlineVariant` stroke + body text `onSurface` / secondary `onSurfaceVariant` (holds for each of the three modes; never revert to the fixed dark #292f3d).
- **Dark `surfaceVariant` (#3A424B cool blue-gray) must be visibly lighter than `background` (#121316)**: table headers / tool cards / reasoning blocks / inline code chips / attachment bars all consume this color; if it hugs the base there is no layering. It was computed from `DARK_TONES.surfaceVariant = 0.26` before the blocks were frozen - never hand-write a lighten function (`lightenColor` was removed along with the per-token overrides).

## Common Commands

- `npm start` — Metro (port 13081)
- `npm run android` — Android devDebug build & run (reads `.env.dev`: ENTRY_FILE=src/flavors/index.dev.js, APP_ID=io.github.luo3house.cafebeeai.dev)
- `npm run build:apk` — Signed github-flavor release APK (arm64-v8a only): reads `.env.github` (APP_ID / version / entry), cross-env ENVFILE wins over envConfigFiles; output `android/app/build/outputs/apk/github/release/app-github-release.apk`. **CI only** - local runs fail on the gradle signing strict check (no `android/key.properties`), which is intentional so debug-signed "release" APKs are never distributed. Use GitHub tag workflow for release.
- `npm run lint` — ESLint (config shipped in the repo)
- `npm run tsc` — type checking (`tsc --noEmit`; `src/vendor/**` and `scripts/**` are excluded — do not edit them directly)
- `npm run debug:fs` — sandbox debugger (host-side only, ships nothing in the APK): pulls the debuggable app's `<filesDir>` over `adb exec-out run-as … tar` into `.debug-fs/sandbox` and serves a browser UI (default http://127.0.0.1:8788) to view/edit/write-back/delete `cafebeeai/**`. Every write/delete **force-stops the running app first** (otherwise debounced persist / registry flushes clobber the edit), then optionally cold-restarts via `am start`; `scripts/dev-sandbox-server.ts` + `scripts/dev-sandbox-ui.html`. Flags: `--port` `--pkg` `--serial` `--lan` `--mirror`. Typecheck: `npx tsc -p scripts/tsconfig.json`.
- Verification closure: **`npm run lint` + `npm run tsc` is sufficient; never run `react-native bundle` as a packaging smoke test** (obsolete and no longer an acceptance gate)
- The web build script is kept but **its functionality is not guaranteed** (RNW Paper/navigation compatibility is limited).
